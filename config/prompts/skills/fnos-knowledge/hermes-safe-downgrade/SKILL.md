# Hermes 主动降级安全流程

## 一、先说明中断与窗口要求

执行前明确告知用户：

> 降级会中断当前任务和连接。收到独立检查确认完成之前，请不要刷新、关闭当前对话窗口，也不要重复提交降级或手动操作服务。本窗口可能暂时断开。窗口保留不能保证任务继续运行，必须先准备不依赖当前 Hermes 进程的执行、观察和恢复通道。检查完成后再打开新窗口验收，验收通过前保留原窗口。

只读分析或编写流程不等于降级授权。只有用户明确要求实际降级，且下列前置条件均满足时才执行。缺少条件就停在只读检查并说明缺口，不能冒险试运行。

## 二、确认真实环境与执行保障

1. 确认用户指定设备、应用实例、目标版本和精确提交。使用当前环境的 `TRIM_PKGHOME`、`TRIM_APPDEST`、`TRIM_PKGVAR`、`HERMES_HOME`，解析实际路径，不硬编码卷号或历史 generation。
2. 记录当前 active 选择、源码 HEAD、实际运行解释器/版本、工作区修改、两套前端收据、各服务原始运行/启用状态及未完成更新事务。存在未知状态、并行任务或 recovery-required 时停止，不删锁或标记来继续。
3. 先验证独立 SSH/系统执行器与观察通道，执行器必须在停止或重启 Hermes 后仍可运行并可被用户查询。保存任务标识、阶段、退出码、受限访问的日志与恢复步骤。不得将凭据写入聊天或普通日志。仅把命令加 `&`、`nohup` 或保留聊天窗口，不算已证明独立。
4. 阅读当前应用实际支持的更新锁、generation 选择和切换协议及命令帮助。不能猜 API 参数，不能把 `hermes update` 当作支持任意版本降级的保证，也不能假定本包存在 `hermes fnos-backup`。没有已验证的隔离准备和受控切换方法时，不执行手工原地降级。
5. 先检查目标版对当前数据库、会话、配置和插件格式的向后兼容性。新版成功写入的数据不一定能被旧版读取。没有可靠兼容证据时先在隔离数据副本验证，未通过不得切生产。编译成功不能证明数据兼容。

## 三、一致性备份

1. 先记录原服务状态、取得已有维护锁并停止所有相关写入者，确认任务和写入已静止。停用失败不得继续备份或切换。不能仅关闭 WebApp 后假定 Gateway、Dashboard、定时任务和后台写入已停止。
2. 使用实际存在、经验证且覆盖本实例的备份方法，保留配置、密钥、会话、记忆、技能、插件状态、微信资料及其他持久数据，同时记录源码/依赖/选择器以便恢复执行环境。不要只复制列举的几个文件就宣称完整。
3. SQLite 使用受支持的在线备份协议或已停写的一致快照，正确处理数据库与 WAL/SHM，禁止热拷贝单个 `state.db` 后忽略 WAL。跨文件状态也必须对应同一停写边界。
4. 备份写入独立的新位置，不覆盖已有备份。保留权限和敏感性边界。核验清单、摘要、完整性、数据库可读性和恢复步骤，必要时在隔离副本验证。备份完成不授权自动恢复或覆盖 DATA。
5. 目标准备若要恢复原服务运行，最终切换前再次停写并制作/验证新的切换点一致性备份。不能把早期备份误称最终切换快照。普通失败尝试恢复原来运行的服务，原关闭服务保持关闭。用户明确停服、取消或应用退出时不得擅自拉起。

## 四、在独立目标代准备源码与锁定依赖

1. 在当前活动目录之外建立目标 generation，核实目标 tag 对应的精确 commit 和来源。保留原活动 generation、工作区修改及已有失败代。禁止在活动源码上 `git checkout -f`、`reset --hard` 或覆盖整套资源。
2. 使用目标版本要求的 Python、Node、包管理器与锁文件，在独立环境安装锁定依赖。遵循当前版本官方构建文档。不混用原活动 venv，也不以全局升级 SDK 或修改 lockfile 解决不匹配。
3. `scripts/build/python.mjs` 是调用构建解释器的辅助代码，不是依赖同步命令。核实真实命令、必要环境变量及每一步退出状态后再继续。
4. 检查目标 CLI/module、插件和运行时完整性。禁止使用生产 DATA 试启动未经兼容性验证的旧版程序。

## 五、分别构建并校验两套前端

- WebApp 对应 `apps/desktop/dist-webapp`；Dashboard 对应 `hermes_cli/web_dist`，两者必须分别通过目标版本的官方构建与新鲜度检查，不能只验证其中一套。
- 按目标版本确认命令和构建解释器。例如某版本 `web/package.json` 的 build 会调用官方 `scripts/build/web.mjs`，不要绕过它只执行裸 Vite，也不要跨版本照抄参数。
- 校验 `hermes-build.json` 中 product、输入源码摘要、prepared 输入、环境、平台/架构、Node 及输出摘要，并核验入口 HTML 和其引用资源存在、可读取。预构建资源仅在完整收据与当前目标环境全部匹配且官方验证通过时复用。相同版本号或 HTTP 200 本身不够。
- `.hermes-stale` 是构建失败保护。禁止批量删除标记来隐藏失败。由目标版本官方构建/验证流程在成功后正常清理。失败时保留诊断、旧代和目标代，不把旧版资源复制到新版活动源码中混用。

## 六、受控切换、重启与验收

1. 由独立执行器在已有锁和维护协议内确认最终备份、原服务状态及源/依赖/两套资源仍匹配，再执行受控切换。服务管理走当前应用已验证接口，不全局 `pkill`、不按端口杀进程、不长期 root 运行 Hermes。
2. 按该协议重启并核对实际选择器、进程来源、解释器和版本。检查 Gateway、WebApp、Dashboard 的健康状态及 `assets_ready`，并确认实际启用状态与计划一致。
3. 检查新请求能取得入口 HTML 及引用的 JS/CSS，确认无 stale/503、资源错配、缺依赖或认证错误。保留真实时间与结果。不把监听端口、旧窗口仍能聊天或单个 HTTP 200 当作完成。
4. 独立检查完成后通知用户可以打开新窗口，通过正常 fnOS 网关与认证入口验证 WebApp、Dashboard，以及必要的会话读取和对话链路。模型不可用则单独报告，不伪称全链验收通过。不要暴露票据、Cookie 或 Token。
5. 新窗口验收通过才报告降级成功并允许关闭原窗口。失败或状态未知时停止后续变更，先读实际状态。不自动重复切换，不清 recovery 标记、不删失败代或备份。恢复旧执行环境仅按预先授权、已验证且数据仍兼容的方案。恢复/覆盖用户 DATA 必须另有明确授权。

本技能是操作约束，不代表安装了自动降级或备份模块，也不保证任意旧版本兼容当前用户数据。
