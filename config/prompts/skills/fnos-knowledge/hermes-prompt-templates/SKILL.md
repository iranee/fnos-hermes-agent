# 随包规则模板更新检查

应用包里带一份 `SOUL.md` 和 `AGENTS.md` 模板。升级应用包不会覆盖数据目录里已有的这两个文件，它们可能已被用户改过。模板新增的规则由你读出来，问过用户再合并。

## 一、每个新会话检查一次

回复用户第一条消息之前，用文件读取工具读下面这个文件，不要用终端命令：

```
/var/apps/hermes-agent/var/prompt-templates.json
```

- 读不到，或 `pending` 不是 `true`：什么都不用说，直接处理用户的请求。
- `pending` 是 `true`：再读 `ack` 字段指向的文件。内容和 `id` 相同说明已经处理过，同样不用说。读不到或内容不同，按第二节做。

同一个会话只查一次。定时任务、子代理和无人值守的会话不做这项检查。用户说升级了应用包、更新了内核，或者让你检查更新之后，再查一次。

## 二、有待处理的更新

`files` 里 `changed` 为 `true` 的每一项带三个路径：

| 字段 | 含义 |
|---|---|
| `template` | 这次应用包带的新模板 |
| `previous` | 上次处理时的模板，可能是 `null` |
| `local` | 用户正在用的文件 |

1. 读 `template` 和 `local`，`previous` 不是 `null` 时也读。
2. 找出模板这次新增或改动的规则。有 `previous` 就对比 `previous` 和 `template`。没有就找 `template` 里有、`local` 里没有的内容。
3. `local` 里多出来的内容、和模板写法不同的内容是用户自己的定制，不算差异，不要建议删除或改回去。
4. 只有措辞、排版调整，或者 `local` 已经有同样意思的规则：不打扰用户，直接写 `ack`（见第 6 步）。
5. 有实质变化时，先答完用户当前的问题，再在同一条回复末尾汇报：哪个文件，新增或改了哪几条规则，每条一句话说明作用。然后问用户要全部合并、只合并其中几条，还是不合并。
6. 用户答复后：
   - 合并：只把用户同意的规则写进 `local` 里合适的位置，其余内容不动。不要用 `template` 整个覆盖 `local`。写完读回核对，告诉用户改了哪几处，新规则从下一个会话起生效。
   - 不合并：不改文件。
   - 两种答复都要把 `id` 的值原样写进 `ack` 指向的文件，文件里只放这 12 个字符。写过之后不再提醒，等应用包带来下一版模板才会再问。
7. 用户没答复或说以后再说：不写 `ack`，下个会话再问一次。

## 三、边界

- `template` 和 `previous` 只读，不要修改。
- 没有得到用户同意，不改 `local`。
- 汇报里只写规则内容，不贴整份模板。
